# 低成本 RAG 知識問答系統（Apps Script 版）

一套只靠 **Google 試算表 + Apps Script + GitHub Pages** 就能跑的知識問答機器人：上傳文件、核可後，使用者用聊天頁提問，系統依核可的知識回答並附出處。除了模型 API 的用量費以外不需要伺服器、資料庫或任何月費。

一套程式可以服務不同領域：領域內容（提示詞、回答格式、Skill、轉介資源、介面文字）都在後台設定或用範本一鍵載入，不用改程式。

```
聊天頁 web/chat/（GitHub Pages，靜態）
      │ POST
      ▼
Apps Script 網頁應用程式（apps-script/）──▶ Gemini／OpenAI API（分流、向量、生成、檢查）
      │
      ▼
Google 試算表（設定、Skill、文件、知識段落、對照表、對話紀錄）
後台：同一個網址加 ?page=admin，帳號密碼登入
```

## 系統需求

- 一個 Google 帳號（建試算表與 Apps Script）
- Gemini API 金鑰（必要）；OpenAI API 金鑰（選用，要用 OpenAI 模型才需要）
- 一個 GitHub 帳號（放聊天頁；公開 repo 才能用免費的 GitHub Pages）
- 不需要安裝任何東西；`sync-trace.js` 只有改前端共用程式時才用到 Node.js

## 安裝

### 1. 準備 API 金鑰

1. 到 Google AI Studio 建立一把 Gemini API 金鑰。
2. （選用）到 OpenAI 平台建立一把 API 金鑰。
3. 金鑰先放著，第 2 步會用到。**不要貼進任何程式檔或 repo。**

### 2. 建立後端（試算表 + Apps Script）

兩種方式擇一。

#### 方式 A：三個指令（需要 Node.js）

[clasp](https://github.com/google/clasp) 是 Google 官方的命令列工具，可以從電腦直接建立與推送 Apps Script 專案。第一次用前到 <https://script.google.com/home/usersettings> 把「Google Apps Script API」打開（只需一次）。

```bash
cd apps-script
./install.sh "機器人名稱"
```

腳本會：開瀏覽器讓你用 Google 帳號登入並授權 clasp → 建立一份新試算表與綁定的 Apps Script 專案 → 把所有程式推上去。結束時畫面會列出剩下要在瀏覽器做的事（設定金鑰、`setup()`、部署）。Windows 用 Git Bash 或 WSL 執行；或照腳本內容手動打那三行 `npx @google/clasp …`。

之後更新程式只要 `npx @google/clasp push -f`，再到編輯器部署新版本。

#### 方式 B：手動貼上

1. 建立一份**新的** Google 試算表（一個機器人一份試算表）。
2. 選單「擴充功能 → Apps Script」。
3. 把 `apps-script/` 底下的檔案逐一建立並貼上：
   - 指令碼檔 9 個：`Code`、`Chat`、`Knowledge`、`Llm`、`Store`、`Setup`、`Admin`、`Graph`、`Eval`（新增「指令碼」，名稱不含 `.gs`）
   - HTML 檔 3 個：`AdminUI`、`TraceView`、`AnswerView`（新增「HTML」，**名稱必須完全一致**）
4. 「專案設定」→ 勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」→ 把 `apps-script/appsscript.json` 的內容貼進去。
5. 左側「服務」＋ → 新增 **Drive API**（上傳 Word 檔時會用到）。

#### 兩種方式都要做的收尾

6. **設定 API 金鑰**：回到試算表重新整理，選單「AI 助手後台 → 設定 API 金鑰」，選 Gemini、貼上金鑰、確定。金鑰存進 Apps Script 的「指令碼屬性」（也可以自己到「專案設定 → 指令碼屬性」新增 `GEMINI_API_KEY`／`OPENAI_API_KEY`，效果相同）。
7. 選單「AI 助手後台 → 初始化工作表（setup）」。第一次會跳授權畫面，依序允許。執行完會建立所有工作表、通用預設設定、一組測試用邀請碼，並把你的帳號加進「管理員」。
8. 到 Apps Script 編輯器：右上「部署」→「新增部署作業」→ 類型「網頁應用程式」：執行身分 **我**、誰可以存取 **所有人** → 部署，複製 `/exec` 網址。
9. 試算表選單「AI 助手後台 → 設定後台帳號密碼」建立一組後台登入帳號。

#### 給別人用的「建立副本」範本

如果你要讓同事自己開一個機器人，最省事的做法是：用上面任一方式建好一份**乾淨的**試算表（跑過 `setup()`、**沒有**填金鑰、沒有知識、沒有邀請碼以外的資料），把它分享為「知道連結的人可檢視」，再給他們這個網址把 `/edit` 換成 `/copy`。對方按「建立副本」會連同 Apps Script 一起複製，然後只要做收尾的 6–9 步。範本試算表裡**不要**留任何金鑰或個資，副本會把它們一起帶走。

### 3. 部署聊天頁（GitHub Pages）

1. 把這個 repo fork 或複製到自己的 GitHub 帳號（**公開** repo）。路徑說明以 repo 根目錄為準。
2. 編輯 `web/chat/config.js`，把 `GAS_URL` 改成第 2 步拿到的 `/exec` 網址。這個檔案只有後端網址，沒有金鑰，公開沒有問題。
3. repo 的 Settings → Pages → Source 選 **GitHub Actions**。
4. 到 Actions 分頁，若沒有自動開始，手動執行「Deploy web to GitHub Pages」一次。
5. 完成後聊天頁網址是 `https://<你的帳號>.github.io/<repo 名稱>/chat/`。

不想用 GitHub 也可以：`web/chat/` 是純靜態檔，放到任何能放靜態網頁的地方都行。

### 4. 初始設定與放入知識

1. 開後台：`/exec` 網址加上 `?page=admin`，用剛才建立的帳號登入。
2. 「機器人設定」：
   - 最上面選**版本**（基本／多取向分流／全功能），一鍵套用一組開關。
   - 「基本」區填機器人名稱、歡迎訊息，決定要不要邀請碼。
   - 「角色用詞」填提問者、談論對象、升級對象的稱呼（例如：同仁／申請案／承辦人），所有提示詞會自動套用。
   - 「模型」區選各步驟用的模型，按「測試」確認金鑰可用。
3. （選用）「其他設定 → 載入專案範本」：上傳 `templates/` 裡的 JSON，一次匯入一個領域的 Skill、轉介資源、同義詞、禁止用語、提示詞與介面文字。repo 附兩份範例：`preschool-inclusion.json`（學前融合教育）、`internal-helpdesk.json`（機構內部行政服務台）。
4. 「知識庫」上傳 PDF、Word、TXT、Markdown 或貼上文字 → 「看段落」確認切得對 → **核可**。只有核可的文件會被拿來回答。
5. 「測試對話」問一題，右側會顯示每一步做了什麼（分流、載入的 Skill、檢索到的段落與分數、檢查結果）。
6. 聊天頁用「邀請碼」工作表裡的邀請碼進入即可使用。

## API 金鑰放哪裡、絕對不能放哪裡

| 位置 | 可以嗎 | 說明 |
| --- | --- | --- |
| Apps Script「專案設定 → 指令碼屬性」 | **這是唯一正確的位置** | 試算表選單「設定 API 金鑰」就是寫到這裡；只有專案擁有者看得到，程式用 `PropertiesService` 讀取，不會傳到前端 |
| `web/chat/config.js` 或任何前端檔 | **不行** | 前端是公開的，任何人按 F12 都看得到 |
| `.gs` 程式碼裡 | **不行** | 會跟著程式被複製、貼到 repo、出現在 zip 裡 |
| 試算表任何儲存格 | **不行** | 有試算表檢視權限的人都看得到 |
| GitHub repo、zip、截圖、對話紀錄 | **不行** | 一旦公開就要立刻作廢重發 |
| 當範本分享的試算表 | **不行** | 「建立副本」會把指令碼屬性一起複製給對方 |

- 後端拿到請求後才用金鑰呼叫模型；使用者端從頭到尾不會碰到金鑰。
- 多個機器人可以共用同一把金鑰（各自在自己的指令碼屬性填一次），但分開比較好算用量、出事好隔離。
- 懷疑金鑰外洩：到 AI Studio／OpenAI 平台刪掉舊的、建新的，更新指令碼屬性即可，不用重新部署。
- 建議在 Google Cloud／OpenAI 後台設**用量上限**；後台也有「每日回答上限」`daily_limit` 和每小時上限 `hourly_limit` 擋異常用量。

## 更新程式

後端更新**不會自動**發生：把改動的 `.gs`／HTML 檔重新貼進 Apps Script（或 `npx @google/clasp push -f`）後，一定要 **部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新版本」→ 部署**。網址不變。沒做這步，`/exec` 跑的還是舊版本。

- 更新說明若寫「要跑 `setup()`」：代表有新增設定項或工作表欄位；`setup()` 只補缺的、改舊標題，不會覆蓋已有的資料與設定值。
- 前端（`web/chat/`）push 到 repo 後 GitHub Actions 會自動重新部署。
- `web/chat/trace.js`、`answer.js` 是聊天頁與後台共用的；改了之後執行 `node sync-trace.js` 會重新產生 `apps-script/TraceView.html`、`apps-script/AnswerView.html`，再貼回 Apps Script。

## 再開一個機器人

每個機器人 = 一份試算表 + 一個 Apps Script 部署 + 一個指向它的聊天頁，彼此的知識、設定、紀錄、後台帳號完全獨立。

1. 重做「安裝 → 2. 建立後端」，拿到新的 `/exec` 網址。
2. 聊天頁另放一份（另一個 repo，或同 repo 另一個資料夾），`config.js` 填新網址。
3. 後台載入對應的範本或手動設定。

## 功能說明

### 回答流程

```
去識別化（可關）→ L4 分流（意圖、主題、轉介分級，可關）‖ 查詢向量
→ 狀態機（緊急轉介／超出範圍／追問／回答）→ 載入 Skill → 檢索（同義詞擴充＋向量＋關鍵字；可加 AI 重排與配額、知識圖譜）
→ 知識足夠判斷 → 組裝 prompt → 生成 → 檢查（禁止用語、出處核對、L5 AI 檢查、回應度）
→ 未通過重寫一次 → 仍不過改保守回答 → 回覆並寫紀錄
```

### 版本（後台一鍵套用，之後可個別調）

| 版本 | 內容 | 適合 |
| --- | --- | --- |
| 基本 | 問答＋知識庫＋出處；單一 Skill；不分流、不追問、每次完整回答 | FAQ、規定查詢 |
| 多取向分流 | ＋多個 Skill、L4 分流、資訊不足時追問 | 同一個機器人要處理多種題型 |
| 全功能 | ＋個案機制（同一個案數輪後改延續回覆）、AI 重排與配額、知識圖譜參與回答 | 輔導型、對話會延續多輪 |

去識別化、L5 檢查、回應度、出處機制、固定回答欄位、AI 補足、邀請碼、每日上限在每個版本都是獨立開關。

### 後台分頁

| 分頁 | 可以做什麼 |
| --- | --- |
| 機器人設定 | 版本、基本資料、角色用詞、模型；進階：流程開關、檢查、提示詞與回答格式、檢索參數、聊天介面文字 |
| 流程控制台 | 依目前設定畫出流程圖、疊上運作數據、點節點直接改設定、試跑一題標出走過的路徑 |
| Skill | 新增與編輯 Skill、對應主題、「一律載入」、啟用／停用；每次儲存都是新版本，可還原 |
| 知識庫 | 上傳文件、看段落、核可／停用、檢查並修復向量 |
| 知識圖譜 | 匯入圖譜、標註段落、審核候選節點、覆蓋度、依現有文件產生圖譜草稿 |
| 測試對話 | 不需邀請碼試問，看完整流程紀錄 |
| 對話紀錄 | 指標、篩選、知識缺口、常被引用文件、格式穩定度 |
| 問題統計 | 知識不足、L5 問題分類、匯出 CSV |
| 命中率測試 | 專家寫問法＋應找到的文件，算 Hit@K 與 MRR |
| 自動評測 | AI 出題／真實提問／專家題，逐題跑完整流程並評分，專家抽查 |
| 其他設定 | 載入專案範本；同義詞、禁止用語、轉介資源、邀請碼、管理員在試算表編輯 |

### 回答欄位、意圖、檢查項目的編輯器

這三個設定不用看 JSON。每個都有四種檢視：
- **表格**：用中文選型別（一段文字／條列／有出處的建議）、何時出現、必填／摘要／可複製，可排序、增刪
- **用說的**：用自己的話描述想要的行為，按「轉換」由 AI 整理成設定，結果回到表格給你檢查；也可反向「把目前設定寫成描述」
- **預覽**：假資料畫出回答長什麼樣
- **原始格式**：給進階使用者

沒有自訂時顯示內建預設並標註；任何改動都要按「儲存設定」才生效。

### 專案範本

`templates/<名稱>.json` 包含六段：`settings`（設定值）、`skills`、`synonyms`、`forbidden`、`referral`、`kgDefs`。後台「載入專案範本」一次匯入：設定值直接覆蓋，清單預設只加沒有的，勾「取代」才清掉重寫。在後台調好的設定也可以整理成新範本給下一個案子用。

### 知識圖譜（選用）

- 圖譜決定「有哪些概念、彼此什麼關係」；回答內容仍來自核可的文件。
- `enable_kg` 開啟後，依問題比對節點名稱與同義說法、沿關係擴一層；節點定義與實務要點放進回答 prompt 當背景。`kg_mode=hybrid` 標到節點的段落加分，`only` 只用標到節點的段落。
- 節點類型、關係、讀者對象在「圖譜定義」工作表自行定義；可匯入 `knowledge-graph.json`，或依現有文件由 AI 產生草稿。

### 流程觀測面板

在「邀請碼」工作表把某組的「觀測」欄設為 TRUE，用它進聊天頁時會出現「流程」按鈕，每則回覆可看分流結果、Skill、檢索分數、prompt、檢查與耗時。正式使用的邀請碼不要開。

## 個資與去識別化

- `enable_deid` 開啟後，每則訊息在送模型與寫紀錄前先去識別化：`deid_mode=ai` 用模型找出人名、小名、綽號、家人稱呼、機構名換成代稱（L4 開著時併在同一次呼叫，不增加時間）；`rule` 只用簡單規則。兩種都會刪電話、Email、身分證字號。
- 代稱直接跟著「角色用詞」走（談論對象→「孩子A」、人員→「老師A」…），不用另外設。
- 原名與代稱的對照表只留在使用者的瀏覽器，試算表裡的對話紀錄與流程紀錄只有代稱。
- 模型可能漏抓，請把它當「盡力去識別化」而非「完全匿名」；需要告知使用者時，把文字放在 `ui_gate_text`（邀請碼頁）或 `welcome`。
- 關閉去識別化時，對話原文會直接寫進試算表，請自行評估。

## 安全注意事項

- 後端網頁應用程式「誰可以存取：所有人」是必要的（聊天頁要能呼叫），但程式本身只開放 `chat`、`check`、`feedback`、`ui` 四個動作，後台所有功能都要登入。
- 邀請碼錯誤次數有全域限制；後台帳號連續輸錯 5 次鎖 15 分鐘；登入有效 6 小時。
- 關閉邀請碼（`enable_invite`）等於公開，任何人拿到網址都能用、都會產生 API 費用，務必設 `daily_limit`。
- 寫入試算表的內容都經過公式注入防護；前端輸出都有跳脫。
- 使用者不需要 Google 帳號，也不用分享試算表給任何人；試算表的編輯權限只給管理者。
- 知識段落保存的是文件原文，請確認文件授權。

## 常見問題

**開後台出現「找不到名為 AdminUI 的 HTML 檔案」**
HTML 檔沒加，或加了但沒有重新部署新版本。

**改了設定沒生效**
設定有約 1 分鐘快取；從後台「儲存設定」會立刻清快取，直接改試算表要等一下。

**回答一直是「目前知識庫裡沒有足夠內容」**
知識庫沒有核可的文件，或 `min_score` 門檻太高。到「測試對話」看檢索分數。想讓 AI 在知識不足時補答，關掉 `knowledge_only`（回答會標「AI 補充」）。

**模型清單是空的／測試失敗**
檢查指令碼屬性的金鑰名稱是否正好是 `GEMINI_API_KEY`／`OPENAI_API_KEY`，以及該金鑰在供應商後台是否啟用。

**換了向量模型或維度**
舊文件的向量不能再用，用「知識庫 → 檢查並修復向量」重算或重新上傳。

## 限制

- Apps Script 單次執行上限 6 分鐘、每日有配額；一次完整回答約 8–20 秒（含分流、生成、檢查多次模型呼叫）。
- 向量存在試算表（壓成 int8），數千段以內順暢；上萬段建議改用資料庫。`Knowledge.gs` 的檢索部分是可替換的邊界。
- PDF 轉文字用模型處理，單檔建議 30 頁以內。

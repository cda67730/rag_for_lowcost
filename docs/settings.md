# 設定參考

> 本檔由 `tools/gen-settings-doc.js` 依 `apps-script/Setup.gs` 的 `SETTINGS_DEFAULT` 產生，請改那邊再重新產生，不要手改。

兩個後端讀同一組設定 key。Apps Script 版存在「設定」工作表；Python 版存在 `bot_settings`（標「Flow 可覆蓋」的可在 `flow_settings` 另設），標「知識庫」的在 Python 版是知識庫的屬性，建庫時決定。

- 布林值：試算表裡填 `TRUE`／`FALSE`；後台是開關。
- 文字設定裡的 `{user}` `{subject}` `{escalate}` `{domain}` 會換成「角色用詞」。
- 留空＝用程式內建預設，不會報錯。
- 回答欄位、意圖選項、檢查項目在後台有表格與「用說的」編輯器，不需要手寫格式。

## 版本

選版本＝一次寫入下表這幾個開關；之後可個別調整。

| 設定 | 基本（`basic`） | 多取向分流（`multi`） | 全功能（`full`） |
| --- | --- | --- | --- |
| `enable_triage` | 關 | 開 | 開 |
| `enable_case_flow` | 關 | 關 | 開 |
| `enable_rerank` | 關 | 關 | 開 |
| `enable_kg` | 關 | 關 | 開 |
| `max_followups` | `0` | `1` | `1` |

- **基本**：問答＋知識庫＋出處。單一 Skill（預設 Skill 一律載入），不分流、不追問、每次完整回答
- **多取向分流**：＋多個 Skill、L4 分流（意圖、主題、轉介分級）、資訊不足時追問
- **全功能**：＋個案機制（延續回覆）、AI 重排與配額、知識圖譜參與回答

## 流程開關

| key | 預設 | Python 版位置 | 說明 |
| --- | --- | --- | --- |
| `enable_triage` | 開 | Bot（Flow 可覆蓋） | L4 分流：開＝AI 判斷意圖、焦點、轉介、主題、是否追問；關＝不呼叫分流 AI，主題用關鍵字比對，直接檢索知識庫回答（較快較省，但不會偵測緊急轉介、不追問、不判斷超出範圍） |
| `max_followups` | `1` | Bot（Flow 可覆蓋） | 最多追問幾輪 |
| `enable_case_flow` | 開 | Bot（Flow 可覆蓋） | 個案機制：開＝L4 判斷是否換了新個案、同一個案給 full_answer_rounds 次完整回答後改延續回覆；關＝整段對話都帶進去、每次都完整回答，不切換延續回覆（FAQ 型專案用） |
| `full_answer_rounds` | `2` | Bot（Flow 可覆蓋） | 同一個個案給幾次完整回答；之後改成延續回覆（只回應新內容＋下一步選項） |
| `enable_rerank` | 開 | Bot（Flow 可覆蓋） | 是否用 AI 依「能不能回答提問焦點」重新排序檢索結果（每題多一次 AI 呼叫） |
| `enable_kg` | 關 | Bot（Flow 可覆蓋） | 知識圖譜參與回答：開＝依問題比對圖譜節點（名稱、同義說法），沿關係擴一層，節點定義與實務要點放進回答 prompt 當背景；需要先在「知識圖譜」分頁匯入圖譜並標註段落 |
| `kg_mode` | `hybrid` | Bot（Flow 可覆蓋） | 圖譜怎麼影響檢索：hybrid＝標到節點的段落加分，其他段落照常；only＝只用標到節點的段落，沒對到任何節點就視為沒有可用知識 |
| `enable_deid` | 關 | Bot | P03 去識別化：開＝訊息裡的人名、小名、家人稱呼、機構名換成代稱並刪電話／Email／證號後，才送模型與寫紀錄（方式見 deid_mode）；關＝原文直接使用 |
| `deid_mode` | `ai` | Bot | 去識別化方式：ai＝用模型找出人名、小名、綽號、機構名換成代稱（L4 分流開著時併在同一次呼叫，不多花時間；L4 關閉時另外呼叫一次；失敗時自動改用規則）；rule＝只用規則（「小＋一字」）。兩者都會刪電話、Email、證號 |
| `deid_labels` | （空） | Bot | 代稱前綴（通常不用填）：留空＝談論對象用「談論對象稱呼」、人員用「提問者稱呼」、家人／某機構／某人固定。要改才填，一行一個「類別＝代稱」，類別：subject、family、staff、org、other |
| `enable_citation` | 開 | Bot（Flow 可覆蓋） | 出處機制：開＝回答裡的建議（items 欄位）每條都要引用知識編號，P09 核對出處與數量；關＝不要求引用、不做 P09，回答欄位可以只有文字（FAQ 型或不需逐條溯源的專案用） |
| `knowledge_only` | 開 | Bot（Flow 可覆蓋） | 只用知識庫回答：開＝知識不足時保守回答；關＝知識不足時由 AI 協助補足（照樣檢查，並標示「知識庫內容不足」） |
| `enable_answer_schema` | 開 | Bot（Flow 可覆蓋） | 回答欄位：開＝回答依「回答欄位」設定分成固定幾段（標題、建議清單…）；關＝自由作答，一段文字加可選的參考做法，不強制格式（FAQ 型或想讓模型自然回答時用） |

## 長文字設定的預設值

### `check_items`

```
依據＝每個建議是否大致能從它引用的知識推得；合理的延伸不算編造，只有知識完全沒提到、或與知識矛盾才算問題。
轉介＝{user}描述中有明確需要專人的訊號（安全、法律、長期無效）而回答完全沒提。
語氣＝說教、責怪{user}或{subject}、或下專業判斷。
```

### `system_prompt`

```
你是{domain}的助手，協助{user}處理工作上遇到的問題。
【核心原則】
- 只根據提供的知識給建議，每條建議標註知識編號（K1、K2…）
- 知識不足以回答時，直接說明，並建議可以詢問的專業人員
- 先理解情境再給建議；建議要少而可立即執行
【回答通則】
- 使用台灣繁體中文，語氣具體、不說教
- 依載入的 Skill 決定流程與輸出內容
```

### `answer_schema`

```
[
{"key":"reply","type":"text","label":"","hint":"直接回應{user}的問題（兩三句）","modes":"both","required":true,"summary":true},
{"key":"steps","type":"items","label":"建議做法","label_continue":"可以再試試","hint":"做法名稱／具體怎麼做（一兩句）","modes":"both","required":true,"summary":true,"count":"1-3","count_continue":"0-2"},
{"key":"notes","type":"list","label":"補充說明","hint":"要留意的事項","modes":"both"}
]
```

### `answer_rules`

```
有出處的建議 1–3 個；每個建議的 refs 只能用上面提供的 K 編號，至少一個；不得下專業判斷或使用標籤化用語。
```

### `fallback_rules`

```
只能提供低風險、一般常識範圍內的做法；不得下專業判斷；來自一般知識的建議 refs 填空陣列；最後建議{user}向{escalate}或專業人員確認。
```

### `intents`

```
新問題＝換了一個完全不同的狀況或主題
補充同一問題＝回答追問或補充細節、說試過的結果
要求特定協助＝要範本、步驟清單、其他做法、找專人等具體東西
與主題無關＝閒聊、算數、與本系統服務範圍無關
```

### `triage_rules`

```
轉介等級：
- 緊急：現在就要找人，例如正在發生的安全或法律風險
- 需要專人：這幾天內要找人，例如做法試了很久都無效、爭議升高
- 建議諮詢：AI 可以回答，專人能幫更多
服務範圍：與本系統的知識領域無關，算超出範圍。
資訊足夠：至少知道問題發生的情境或經過其中一項；非常籠統時算不足。
```

### `followup_prompt`

```
{user}的描述資訊不足。請先用一句話回應，再提出最多 2 個最關鍵、好回答的追問。
```

### `continue_prompt`

```
{user}已經拿到完整建議了，這次不要再重複完整格式。
- reply：用兩三句話直接回應{user}這次說的（新的狀況、試過的結果、或要求），像同事對話一樣自然
- {user}說某個做法有效或無效時，針對這點調整；有新的知識可用時，最多再給 1–2 個「之前沒給過」的做法
- {user}要求特定東西時，只做那一件事，放在對應欄位
- 最後提供下一步選項，讓{user}選要往哪個方向走
```

### `continue_options`

```
換一個不同的做法
給我更詳細的步驟
這個情況需要找誰協助？
```

### `msg_no_knowledge`

```
謝謝你說明這個狀況。目前知識庫裡沒有足夠、經過檢查的內容可以給你具體建議。建議先和{who}討論。
```

### `msg_check_failed`

```
謝謝你說明這個狀況。我整理出的建議沒有通過依據檢查，為了避免給你不夠可靠的內容，這次先不提供具體做法。建議先和{who}討論。
```

### `msg_ai_fallback`

```
目前知識庫內容不足，以下由 AI 協助補足，尚未經審核，請斟酌使用；必要時請和{escalate}確認。
```

## Python 版另外的設定位置

這些不是 Bot 設定 key，在 Python 版另有地方：

| 項目 | 位置 |
| --- | --- |
| 知識庫掛載（標籤、最少段數、權重、啟用） | `bot_knowledge`，Bot 後台「知識庫」分頁 |
| 知識庫可見範圍 | `knowledge_bases.visibility` ＋ `kb_allowed_bots` |
| 模型供應商金鑰、資料庫連線、JWT 密鑰、CORS、紀錄保留天數 | 伺服器環境變數（見 `server/README.md`） |

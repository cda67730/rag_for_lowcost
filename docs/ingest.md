# 文件匯入規格（Python 版）

上傳一份文件到「它變成可以被檢索的段落」之間發生的事。對應 `server/services/ingest.py` 與 `POST /api/admin/kbs/{kb}/documents`。

## 1. 流程

```
上傳 ─▶ 檢查（大小、類型、重複）─▶ documents.status=processing，存原始檔，回 job_id
      │
      └▶ 背景任務：
          1 解析成「帶位置標記的純文字」
          2 切段
          3 段落類型標註（AI，一批 20 段）
          4 向量（依知識庫的 embed_model，一批 100 段）
          5 （auto_kg_tag 開）圖譜標註
          6 寫入 chunks，documents.status=pending，chunk_count=n
      失敗 ─▶ status=failed，error 寫原因；已寫入的段落刪除
審核 ─▶ reviewer／admin 核可 → approved（才會進檢索）；停用 → disabled
```

一份文件一個交易寫入段落：要嘛全部段落都在，要嘛一段都沒有。重新處理（換切段參數、修復）會先刪舊段落再重做，圖譜標註一併重做。

## 2. 上傳檢查

| 項目 | 規則 |
| --- | --- |
| 大小 | 單檔 50 MB；貼上文字 200,000 字 |
| 類型 | 依副檔名＋檔頭判斷，不只看副檔名；不支援的直接拒絕 |
| 重複 | 同一個知識庫內 `sha256` 相同 → 回 409 並附既有文件，前端可選「仍要上傳」 |
| 加密檔 | 有密碼的 PDF／Office 檔 → 拒絕，提示先解除密碼 |

## 3. 各格式解析

所有解析器輸出同一種中間格式：一串 `(位置, 文字)`，位置寫進段落的 `page` 欄位，回答出處會顯示它。

| 格式 | 套件 | 位置標記 | 做法與注意 |
| --- | --- | --- | --- |
| PDF | `pypdf`，表格多的頁改用 `pdfplumber` | 頁碼 `p.3` | 逐頁取文字；頁首頁尾重複行（出現在 ≥60% 頁面的同一行）去掉；連字號斷行與中文不該斷的換行合併。**整頁抽不到文字**（掃描頁）記為「此頁無文字」，整份抽不到就 `failed`，訊息提示掃描檔第一版不支援 |
| Word `.docx` | `python-docx` | 標題路徑 `第二章 > 2.1` | 依段落順序取文字；標題樣式（Heading 1–3）當作切段邊界與位置；表格逐列轉成「欄名：值；欄名：值」；頁首頁尾、註腳略過。舊版 `.doc` 不支援，提示另存 `.docx` |
| PowerPoint `.pptx` | `python-pptx` | 投影片 `第 5 張` | 每張投影片一個單位：標題＋各文字框（依位置由上而下）＋表格＋**備忘稿**（常是真正的說明）；圖片略過。一張投影片內容很少時與下一張合併 |
| Excel `.xlsx` | `openpyxl`（`read_only`、`data_only`） | 工作表與列 `工作表1 第 2–30 列` | 第一個非空列當欄名；每列轉成「欄名：值；…」一行；每個工作表獨立切段；隱藏工作表略過；公式取計算後的值。超過 5,000 列的工作表只取前 5,000 列並在 `error` 註明 |
| 純文字 `.txt` `.md` | 內建 | 標題（Markdown `#`）或無 | 自動偵測 UTF-8／Big5；Markdown 標題當切段邊界 |
| 貼上文字 | — | 無 | 同 `.txt` |

不支援（第一版）：掃描檔 OCR、圖片、`.doc`、`.ppt`、`.xls`、`.odt`、HTML 網址抓取。

## 4. 切段

參數取自知識庫：`chunk_size`（預設 500 字）、`chunk_overlap`（預設 80 字）。演算法與 Apps Script 版 `chunkText_()` 相同，加上結構邊界：

1. 先依結構切成單位（PDF 的頁、Word 的標題段、PPT 的投影片、Excel 的工作表）。
2. 單位內依空行分段落，累積到接近 `chunk_size` 就收一段；下一段開頭帶上一段末尾 `chunk_overlap` 字。
3. 單一段落超過 `chunk_size × 1.6` 時硬切。
4. 段落不跨結構單位（不會一半在第 3 頁、一半在第 4 頁），除非單位本身太短（< 100 字）才與下一個合併，位置標成範圍 `p.3–4`。
5. Excel 的列不從中間切；一段放滿為止的整列。

## 5. 段落類型

每段標一個類型，供檢索的配額使用（`quota_min_actionable`、`quota_max_principle`）：

| 類型 | 意思 |
| --- | --- |
| 具體做法 | 可以直接照做的步驟或策略 |
| 案例 | 具體情境與處理經過 |
| 溝通範例 | 可以直接套用的說法、訊息、對話 |
| 原則／背景 | 理念、理論、統計、定義 |
| 轉介資訊 | 該找誰、怎麼申請、聯絡方式 |

AI 分類，一次 20 段；失敗的留空（視為未分類，不受配額限制），之後可在後台重做或手動改。prompt 沿用 Apps Script 版 `classifyChunks_()`，提問者稱呼取自掛載這個知識庫的第一個 Bot 的 `role_user`，沒有就用「使用者」。

## 6. 向量

- 模型與維度取自知識庫（建庫時固定）。一批 100 段，失敗重試 3 次（指數退避）；仍失敗的段落 `embedding` 為 NULL，文件照樣進 `pending`，後台顯示「n 段缺向量」，可用「修復」補算。
- 向量化的文字＝段落文字前面加上文件標題與位置（`標題｜p.3｜段落內容`），讓短段落也有上下文；存進 `chunks.text` 的只有段落內容。
- 供應商依知識庫的 `embed_model` 自動判斷（Gemini 或 OpenAI，規則同生成模型；可用 `gemini:`／`openai:` 前綴明確指定）。可選的模型與維度見 `data-model.md`。
- Gemini 向量 `task_type` 用 `RETRIEVAL_DOCUMENT`；查詢時用 `RETRIEVAL_QUERY`。OpenAI 沒有這個參數，用 `dimensions` 指定維度（`ada-002` 不能指定）。
- 向量一律正規化後儲存，並檢查回傳維度與知識庫設定相同；不符就整批失敗，不寫入錯誤維度的向量。

## 7. 圖譜標註（選用）

知識庫 `auto_kg_tag` 開啟時，處理完段落就依圖譜定義對每段做標註（寫 `kg_links`，主要／次要標籤），沒對到既有節點的概念寫進 `kg_candidates` 等審核。關閉時（預設）可之後在「知識圖譜」分頁對整個知識庫一次標註。邏輯沿用 Apps Script 版 `Graph.gs` 的標註 prompt。

## 8. 狀態與權限

| 狀態 | 意思 | 會被檢索 | 誰能改成 |
| --- | --- | --- | --- |
| `processing` | 背景處理中 | 否 | （系統） |
| `failed` | 處理失敗，看 `error` | 否 | 重新處理或刪除 |
| `pending` | 處理完，待審核 | 否 | reviewer、admin → `approved`／`disabled` |
| `approved` | 已核可 | **是** | reviewer、admin → `disabled` |
| `disabled` | 停用 | 否 | reviewer、admin → `approved` |

核可與停用寫 `audit_log`（誰、何時）；文件被引用過的話，停用後舊紀錄的出處仍可顯示標題（`sources` 裡存了標題）。

## 9. 錯誤訊息（給使用者看）

| 狀況 | 訊息 |
| --- | --- |
| 格式不支援 | 「目前不支援這種檔案；請轉成 PDF、Word、PowerPoint、Excel 或純文字」 |
| 掃描檔 | 「這份 PDF 沒有可抽取的文字，可能是掃描檔；目前版本不支援掃描檔」 |
| 加密檔 | 「檔案有密碼保護，請先解除後再上傳」 |
| 太大 | 「檔案超過 50 MB」 |
| 模型失敗 | 「向量或分類服務暫時失敗，已處理的部分保留，可稍後按『修復』」 |

## 10. 實作狀態

`server/services/parsers.py`（解析）、`chunking.py`（切段）、`ingest.py`（上傳、處理、修復、背景任務）已完成並有測試；切段與段落類型的 prompt 與 Apps Script 版逐字比對。圖譜自動標註（§7）已完成：知識庫開 `auto_kg_tag` 且已匯入圖譜時，處理完順便標註；失敗不影響匯入。上傳的 API 端點隨後台 API 一起做。

## 11. 與 Apps Script 版的差異

| | Apps Script | Python |
| --- | --- | --- |
| PDF | 交給模型讀（30 頁以內） | `pypdf`／`pdfplumber`，不用模型、不限頁數 |
| Word | Drive API 轉 Google 文件再取文字 | `python-docx`，保留標題結構 |
| PowerPoint、Excel | 不支援 | 支援 |
| 處理方式 | 分批＋觸發器 | 背景任務，一份一個交易 |
| 向量儲存 | base64 int8 | pgvector |
| 段落類型 | 一批 25 段；模型多回的類型會寫到下一批的位置 | 一批 20 段；只取這一批的長度 |
| 向量化的文字 | `標題\n段落` | `標題｜位置｜段落` |
| `chunk_overlap`＝0 | 視為未填（用 80） | 真的不重疊 |

# 後台（Python 版）

Python 版伺服器的管理介面。原生 JavaScript，不需要建置工具；跟聊天頁一樣放在任何靜態空間（GitHub Pages 即可）。

## 設定

編輯 `config.js`：

```js
window.ADMIN_CONFIG = { API_URL: "https://你的伺服器網址" };
```

伺服器的 `CORS_ORIGINS` 要包含後台所在的網址（例如 `https://<帳號>.github.io`）。

## 登入

帳號由伺服器建立：第一個 owner 用 `python -m app.cli create-workspace`，之後的成員在後台「工作區 › 成員」新增（會給一次性密碼）。登入憑證只存在這個分頁（關掉就要重新登入），8 小時後過期。

## 功能

| 位置 | 內容 |
| --- | --- |
| 工作區 | 機器人、知識庫列表與新增；成員與角色（owner）；稽核紀錄（owner） |
| 機器人 | 設定（版本、各區欄位、回答欄位／意圖／檢查項目的表格與「用說的」轉換、模型測試）、掛載知識庫、Skill（含版本與還原、專案範本匯入匯出）、同義詞／禁止用語／轉介資源、邀請碼、流程與流程覆蓋設定、測試對話（附流程紀錄）、紀錄（篩選、單筆流程、CSV）、統計、流程控制台、評測 |
| 知識庫 | 文件上傳（拖放、多檔、貼文字）與處理進度、審核、段落類型、重新分類、圖譜標註、下載原始檔；知識圖譜（匯入匯出、覆蓋度、候選審核、產生草稿、Ontology）；知識庫設定與白名單 |

看得到哪些頁面依角色而定（見 `docs/admin-api.md`）；畫面只是方便，權限一律由伺服器檢查。

流程紀錄與回答的呈現沿用聊天頁的 `../chat/trace.js` 與 `../chat/answer.js`，所以 `web/` 要整個一起部署。
